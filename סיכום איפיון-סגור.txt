אני רוצה לבנות ב-Zite מערכת מלאה לניהול משק חקלאי,
על בסיס מערכת Airtable קיימת ומחוברת.

המערכת היא שכבת הממשק של Airtable.

Airtable נשאר מקור הנתונים, החישובים, הקשרים,
ה-Formulas, ה-Lookups, ה-Rollups, ה-Scripts וה-Automations.

Zite ישמש עבור:
- ממשק משתמש
- ניווט
- טפסים
- הרשאות
- גרפים
- דשבורדים
- פילטרים
- תצוגת נתונים
- העלאת קבצים
- Drill-down
- חוויית משתמש

################################################################
1. כללי יסוד
################################################################

חשוב מאוד:

1. אל תיצור Database חדש.

2. אל תשנה שמות טבלאות ב-Airtable.

3. אל תשנה שמות שדות ב-Airtable.

4. אל תיצור מחדש ב-Zite חישובים שכבר קיימים ב-Airtable.

5. אל תיצור לוגיקה עסקית מקבילה כאשר קיימת כבר לוגיקה ב-Airtable.

6. כל Create / Update / Edit יכתבו ישירות ל-Airtable.

7. לאחר כל פעולה שמשנה מידע:
   - הצג Loading
   - נטרל את הכפתור
   - מנע Double Click
   - המתן לתשובת Airtable
   - קרא מחדש את הנתונים
   - ורק לאחר מכן עדכן את המסך

8. Formula / Lookup / Rollup אינם שדות להזנה ידנית.

9. Checkbox שמפעיל Automation אינו צריך להופיע למשתמש
   כשדה טכני רגיל.

10. אין להציג למשתמש JSON גולמי.

11. אין להציג למשתמש Record IDs.

12. אין להציג Autonumber טכני כאשר אינו משמעותי למשתמש.

13. אין להציג שמות כגון:
    "(from ...)"
    "Rollup"
    "Lookup"
    "-AI"
    "record_id"
    "structure_id"
    "work_records"
    "source_delivery_records"

14. אין להציג מספרי שורה טכניים של Airtable.

15. אם חסר שדה הנדרש לפעולה:
    אל תמציא אותו.
    דווח איזה שדה חסר.

16. אין להחליף null ב-0.

17. כאשר אין מידע:
    הצג "לא זמין".

18. כאשר אין רשומות:
    הצג "אין נתונים לתקופה זו".

3. שמות יפים בממשק
################################################################

שמות השדות של Airtable משמשים רק לחיבור.

למשתמש הצג שמות קצרים ונקיים.

לדוגמה:

"סכום ברוטו Rollup (from חשבוניות)"
→ "פדיון ברוטו"

"סכום נטוRollup (from חשבוניות)"
→ "פדיון נטו"

"משקל Rollup (from חשבוניות)"
→ "משקל"

"תאריך-AI"
→ "תאריך"

"משווק-AI"
→ "משווק"

"מחיר (from תמחור עבודות)"
→ "מחיר"

"יחידת תמחור (from תמחור עבודות)"
→ "יחידת תמחור"

"זן (from תמחור עבודות)"
→ "זן"

"שטח בדונם (from מבנה)"
→ "שטח"

"ק"ג לדונם לשבוע (from תפוקה רבעונית)"
→ "ק"ג לדונם לשבוע"

"מחיר משוער לק"ג (from מחירי גידול משוערים)"
→ "מחיר משוער לק"ג"

אין להציג "(from ...)" בשום מסך רגיל.

44. תוכנית שתילה — אפיון מלא ומחייב
################################################################

אני רוצה לבנות ב-Zite ממשק מלא לתוכנית שתילה על בסיס מערכת Airtable
קיימת ומחוברת.

המטרה:
ליצור ממשק מקצועי, ברור, ויזואלי ונוח מאוד לשימוש,
כאשר Airtable נשאר מקור הנתונים והלוגיקה,
ו-Zite משמש כשכבת הממשק.

==================================================
1. עקרונות יסוד
==================================================

חשוב מאוד:

1. אל תיצור Database חדש.
2. אל תשנה שמות של טבלאות או שדות קיימים ב-Airtable.
3. אל תיצור מחדש ב-Zite חישובים שכבר קיימים ב-Airtable.
4. אל תיצור לוגיקה עסקית מקבילה.
5. כל Create / Update / Edit יכתבו ישירות ל-Airtable.
6. Formulas, Lookups, Scripts ו-Automations הקיימים ב-Airtable
   הם מקור האמת.
7. לאחר פעולה שמשנה מידע, קרא מחדש את הנתונים מ-Airtable.
8. הממשק כולו בעברית וב-RTL.
9. Desktop-first, עם התאמה ל-Tablet ול-Mobile.
10. הממשק צריך להיראות כאפליקציה מקצועית ולא כתצוגת Airtable.

==================================================
2. מבנה המערכת לפי שנים
==================================================

לאחר בחירת שנה,

   YYYYMMDD-YYYYMMDD

7. הקוד נכתב ל"קוד שבוע" בחשבוניות.

8. הקוד נכתב ל"קוד שבוע" בתעודות משלוח.

9. אין הקלדה ידנית של הקוד.

10. מסך העלאת מסמך מנתב את הקובץ לטבלה הנכונה.

11. כל שינוי של עובד נכתב מיד ל-Airtable.

12. מנהל העבודה מקבל את העדכון לאחר הסנכרון.

13. בעל העסק מקבל את העדכון במסכים הרלוונטיים.

15. כל הגרפים והעוגות קריאים.

16. אין טקסט חתוך ללא אפשרות לראות אותו.

17. אין מספרים עם אפסים עשרוניים מיותרים.

18. אין Labels שחופפים אחד לשני.

19. אין צבעים שאי אפשר להבדיל ביניהם.

20. כל Dashboard מותאם גם למובייל.

21. כל הנתונים הרלוונטיים מתרעננים אחרי Automation.

22. אין צורך שהמשתמש יבצע Refresh ידני כדי לראות שינוי שבוצע במערכת.

# פרומפט עיצוב מלא ל-Zite — Color-Coded Premium Agricultural Dashboard

עצב מחדש את **כל שכבת הממשק של המערכת הקיימת**, בהתאם למבנה ולפונקציונליות שכבר הוגדרו, בשפה עיצובית מרשימה מאוד, צבעונית, מודרנית ומקצועית.

המטרה היא ליצור מערכת שכאשר בעל העסק פותח אותה, היא תרגיש מיד כמו **מערכת ניהול פרימיום שנבנתה במיוחד עבור המשק שלו** — ולא כמו Airtable, Spreadsheet, Admin Panel גנרי או מערכת ERP מיושנת.

## 1. קונספט עיצובי

סגנון העיצוב:

**Color-Coded Premium Executive Agricultural Dashboard**

השפה החזותית משלבת:

* Premium SaaS Dashboard
* Executive Business Intelligence
* Modern Agricultural Management
* Rich Data Visualization
* Color-Coded Categories
* Large KPI Cards
* Clean White Cards
* Soft Shadows
* Strong Visual Hierarchy
* Spacious Layout
* Modern RTL Interface

המערכת צריכה להיות **צבעונית ומרשימה**, אך לא ילדותית.

הצבעים צריכים לעזור למשתמש לזהות קטגוריות ונתונים במהירות.

התחושה הכללית:

**חדשני + יוקרתי + חקלאי + פיננסי + טכנולוגי + ברור מאוד.**

אין לשנות שמות טבלאות.

אין לשנות שמות שדות.

אין לשכפל Formula.

אין לשכפל Lookup.

אין לשכפל Rollup.

אין לשכפל Script.

אין לשכפל Automation.

אין להציג JSON גולמי.

אין להציג Record IDs.

אין להציג Autonumber טכני.

אין להציג `(from ...)`.

אין להציג שדות מערכת למשתמש.
